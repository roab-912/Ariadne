# V0.1 — Fondations

Livraison du 5 novembre 2026, limitée à la ligne **0.1 — Fondations** du document d’architecture. Aucune implémentation de la V0.2.

## Livré

- Monolithe modulaire Python : domaine et persistance `investigation`, contrats `connectors`, adaptateur HTTP `apps/api` ; emplacements réservés pour décodeurs et workers.
- FastAPI/Pydantic, contrats OpenAPI versionnés et types TypeScript générés ; React/TypeScript/Vite avec consultation du dossier, choix du run, table d’opérations, détails, preuves, couverture et manifest.
- Compose PostgreSQL 17.7, Redis 7.4.7, API Python 3.12.12 et frontend statique nginx ; migrations et chargement synthétique ponctuels, healthchecks, volumes et exposition sur boucle locale.
- Migration initiale Alembic `0001` : chaînes, adresses, actifs, snapshots sources, observations, opérations et associations, dossiers et graines, runs et associations, contrats séparés d’assertions et d’allocations.
- Identités EVM distinctes par chaîne, montants `NUMERIC(78,0)` bornés à uint256, sérialisation décimale en chaînes, décimales d’actif éventuellement inconnues. Les métadonnées affichées restent distinctes de l’identité.
- Trois mouvements synthétiques dans un dossier **Démonstration**, avec empreinte SHA-256 du fixture, position dans le bloc, provenance et limites visibles. Le scénario ne contient aucun label d’entité ni relation inter-chaînes. Son horodatage est fixe et synthétique.
- Fournisseur indisponible implémentant les cinq méthodes de l’architecture, métadonnées de couverture/pagination/finalité et distinction entre indisponibilité et résultat vide complet. Aucun appel blockchain.
- Création de dossiers locaux et de runs de snapshot `unsupported` avec clé d’idempotence. Aucun résultat synthétique n’est ajouté à un dossier utilisateur.
- Base de test isolée sous un profil Compose, tests Python et Playwright, script HTTP et workflow CI.

Vérifications locales réalisées le 5 novembre 2026. Python hôte 3.14.2, Node hôte 24.12.0 ; tests d’intégration dans les images Linux Compose, Python 3.12.12 et PostgreSQL 17.7.

| `docker compose --profile verification run --build --rm tests` | **33 tests réussis**, aucun sauté ; dont 12 tests d’intégration PostgreSQL/Redis |

| Entiers exacts Python → PostgreSQL → API | Réussi pour 0, `2^53+1`, `10^18+1`, `2^256−1` ; valeurs hors bornes rejetées aussi par SQL direct |
| Identités et relations multi-chaînes | Identités distinctes pour les mêmes octets ; relation observation/adresse/actif d’une autre chaîne rejetée par FK |
| Séparation observations / attribution / allocation | Ajout de résultats dans les tables distinctes sans mutation de l’observation ni du snapshot de labels du run |

Un avertissement de dépréciation AnyIO/Starlette est émis dans les tests sous Python 3.12. Les tests passent ; cet avertissement n’est pas masqué. Le workflow GitHub Actions est fourni mais n’a pas été exécuté sur GitHub pendant cette session.

Le premier passage navigateur avait révélé un débordement horizontal sur mobile ; la largeur minimale des panneaux a été corrigée et le parcours complet a ensuite réussi. Les captures bureau/mobile ont aussi été inspectées. Le défilement horizontal reste limité à la table lorsqu’elle dépasse la largeur disponible.

## Critères de sortie V0.1

| Critère de l’architecture | État et preuve |
|---|---|
| Démarrage documenté depuis un clone | Validé sur le dépôt et un volume PostgreSQL neuf, avec les fichiers de verrouillage, migrations et chargement Compose ; commandes dans le README |
| Montants exacts | Validé aux limites uint256 en domaine, PostgreSQL et API ; affichage du wei conservé dans Chromium |
| Séparation des trois couches | Validée par tables distinctes, absence d’assertion/allocation dans la démo et test d’indépendance des données ajoutées ultérieurement |
| Jalon utilisable et démontrable, mode synthétique explicite | Validé par le contrôle HTTP et le parcours Playwright sur la pile complète |

La V0.1 satisfait ces critères dans son périmètre local déclaré. Un clone sur une autre machine et la CI distante n’ont pas été exécutés pendant cette session.

## Critères encore non couverts

Ces limites sont intentionnelles pour la V0.1 ; aucun résultat de démonstration ne les valide.

- **V0.2** : transactions publiques du corpus, choix et intégration de fournisseurs, historique Ethereum borné, reçus/logs réels, pagination réelle et collecte partielle réelle. Les contrats sont préparés ; aucun adaptateur réseau n’est implémenté.
- **V0.3–V0.5** : jobs durables, workers, reprise, SSE, graphe/chronologie synchronisée, expansion et budgets ; traces et transferts internes, double comptage top-level/trace, annulations, frais, wrap/unwrap, Uniswap ; collecte Base/Arbitrum et CCTP. Les lignes de capacités demeurent toutes `unsupported`.
- **V0.6–V0.7** : import de labels officiels, entités, revue et contradictions ; allocation et conservation de valeur, mélanges, frontières exchanges/mixeurs et hypothèses. Les tables initiales ne constituent pas ces moteurs.
- **V0.8** : authentification OIDC, autorisation et isolation entre utilisateurs, véritables dossiers privés, partage, annotations, sauvegarde des vues, exports et watchlists. La V0.1 est une instance locale mono-utilisateur.
- **V0.9–V1.0** : collecte cohérente avec réorganisations, invalidation de dérivations, quotas, métriques/traces distribuées, stockage objet versionné, restauration de sauvegardes, revue de sécurité, licences des données, TLS, déploiement public, mesures de coûts et benchmarks. Aucune promesse de latence n’est validée.
- Adaptateurs non EVM, signatures de manifests, chaîne de possession qualifiée et véracité initiale des preuves : non implémentés. La base peut distinguer des inclusions orphelines ; aucune détection automatique de réorganisation n’est revendiquée.
